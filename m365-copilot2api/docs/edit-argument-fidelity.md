# Read / Edit 参数保真修复

本改动针对模型从工具文本重建 Edit 参数时的歧义；不承诺消除所有精确字符串匹配失败，也不改变客户端工具协议。

## 行为与边界

1. **Read 展示**：仅识别名为 `Read`、行号严格递增的数字+TAB 列表，将每行的第一个行号分隔 TAB 改成 `→`。其后的缩进 TAB、空格、CRLF 与正文保持原样。逐行处理，不使用会跨行吞空白的 `^\s*`。未知格式、其它工具、重复/倒退行号不改；`system-reminder` 块保持原样。规范化在边界空白清理及原有结果截断之前执行，末尾空行的行号分隔 TAB 不会先被 TrimSpace 吃掉。
2. **覆盖所有出口**：全量 prompt、router 历史、ledger 使用一致的展示；增量 prompt 的工具名映射来自被省略的历史前缀。预算估计和 count_tokens 使用相同展示。客户端原始消息不变；原有的边界空白清理、结果截断和空结果/附件说明仍然适用；这不是一个新建的原始文件字节通道。
3. **JSON 约定**：在 JSON 文本里 `\t` / `\n` 表示解码后的 TAB / 换行，`\\t` / `\\n` 表示字面反斜杠加字母。共享提示覆盖 fenced、plugin/native、router 与回答分支；不要求模型在 JSON 字符串内写裸控制字符。后续 Edit 基于最新内容；失败或状态不明时刷新相关范围，而不是无条件在每次成功 Edit 后额外 Read。
4. **历史参数展示**：合法的对象参数在 prompt 和 ledger JSON 中只保留一层 JSON 表示。使用 RawMessage 保留大整数；不对内部字符串二次反转义。无效、截断或非对象参数仍按原文本展示。内部 arguments 字符串、去重身份和客户端 wire 格式不变。
5. **Windows 路径 salvage**：盘符字段的字面解释与裸控制字符/目录尾反斜杠修复组合执行，不再在 salvage 时退回损坏路径的原输入。已正确转义的反斜杠不会触发路径探针，较早的正常路径也不会遮住后面的异常路径。`old_string` / `new_string` / `content` / `contents` 即使以盘符字样开头，也保留文件正文的 JSON 语义。成功解析后仍执行工具 schema 校验。
6. **失败恢复**：仅当当前尾部工具结果批次中的 Edit 明确报告 not-found、modified-since-read 或 old==new 时，向下一次正常模型请求加入 `[edit-recovery]`。提示先用当前允许的 Read 刷新相关范围，不臆断是多抄 TAB 还是外部修改。最多提示四个文件，路径经 JSON 引用且有长度上限；尊重 `tool_choice` 和工具可用性。后续 Read、assistant/user 消息使旧提示退出，不增加隐藏模型重试轮、不自动重放写操作。原有工具轮数和请求超时限制仍生效。

## 验证

- `go test ./... -count=1 -timeout=180s`
- `go vet ./...`
- `go build ./...`

专项回归包括：TAB/空格/CRLF/空行/提醒块、规范化幂等与未知格式、先规范化后截断、完整历史与真正的 resolver 增量请求、历史大整数及字面反斜杠保真、路径与控制字符组合、两个工具解析器、失败恢复的正反例及 HTTP router/native × stream/non-stream 路径。HTTP 测试 stub 上游，不操作真实文件或连接真实 ChatHub。

## 审计注意

原 `separator_tab_proof.cjs` 的 `digitsOnly` 计数器没有在 `hitA` 时递增，因此“正确剥离命中 0 次”不能作为证据。重复历史中的比对次数也不等于独立失败调用数；重新统计需按 tool-use ID 去重，并使用该 Edit 之前的 Read 快照。本修复保留有样例支持的分隔 TAB 歧义判断，不沿用错误的零命中断言。

源码修改和本地回归不等于部署；运行中的服务需另外按正常发布流程更新。提示词对模型一次写对率的改善仍需上线观察。
